Resumen para integracion en Frontend

Endpoints que usa el Frontend

GET
/v2/auth/google/login?redirect_to=URL
Inicia el flujo OAuth. Redirigir al usuario aca.
GET
/v2/auth/me
Obtiene datos del usuario y su rol. Header: Bearer token
POST
/v2/auth/logout
Cierra sesion (invalida token). Header: Bearer token

Mapeo OU de Google → Rol

El rol se determina por la Unidad Organizativa (OU) del usuario en Google Workspace, consultada via n8n. El frontend NO asigna el rol, solo lo lee.

OU en Google WorkspaceRol en el sistema
/AlumnosESTUDIANTE
/Equipo DocenteDOCENTE
/Administracion y VentasADMINISTRATIVO
(cualquier otra / error n8n)ESTUDIANTE (default)

Pasos para el Frontend

  • 1. Redirigir a GET /v2/auth/google/login?redirect_to=TU_URL_CALLBACK
  • 2. En tu pagina de callback, capturar el ?token=xxx de la URL
  • 3. Guardar el token en localStorage
  • 4. Llamar a GET /v2/auth/me con header Authorization: Bearer token
  • 5. Leer usuario.rol y mostrar el panel correspondiente
  • 6. Para logout: POST /v2/auth/logout + limpiar localStorage

Configuracion: Desarrollo vs Produccion

Desarrollo (mismo servidor)

# Frontend y backend en el mismo puerto
redirect_to = http://localhost:8000/test-login/callback

# .env del backend
GOOGLE_REDIRECT_URI = http://localhost:8000/v2/auth/google/callback

# Google Console → Authorized redirect URIs
http://localhost:8000/v2/auth/google/callback

Produccion (servidores separados)

# Frontend en un dominio, backend en otro
redirect_to = https://portal.ctcsalto.edu.uy/callback

# .env del backend
GOOGLE_REDIRECT_URI = https://api.ctcsalto.edu.uy/v2/auth/google/callback

# Google Console → Authorized redirect URIs
https://api.ctcsalto.edu.uy/v2/auth/google/callback
